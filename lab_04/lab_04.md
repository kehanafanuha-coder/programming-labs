1. Разница между локальным репозиторием Git и удалённым репозиторием GitHub
Локальный репозиторий Git — это хранилище версий проекта, расположенное непосредственно на компьютере разработчика (в папке с файлами проекта, содержащей скрытый каталог .git). Он работает автономно, без подключения к интернету: в нём можно создавать коммиты, переключаться между ветками, просматривать историю изменений и выполнять слияния. Все операции с локальным репозиторием выполняются мгновенно, так как не требуют передачи данных по сети.

Удалённый репозиторий GitHub — это хранилище проекта, размещённое на серверах платформы GitHub (в облаке). Оно служит для централизованного хранения кода, совместной работы команды, резервного копирования и публикации проекта. GitHub выступает в роли «общего» репозитория, с которым синхронизируются локальные копии всех участников проекта.

Ключевые отличия:

Критерий	Локальный Git	Удалённый GitHub
Расположение	На компьютере разработчика	На серверах GitHub
Доступ	Только у владельца машины	У всех, кому предоставлены права
Работа без интернета	Возможна	Невозможна
Назначение	Персональная работа с версиями	Совместная работа, резервное копирование
Синхронизация	—	Через push / pull / clone
2. Команды git add и git commit: назначение и последовательность
git add — добавляет изменения из рабочего каталога в область подготовленных изменений (staging area / index). Это «промежуточный» этап: файл ещё не зафиксирован в истории, но уже отмечен для включения в следующий коммит. Команда позволяет выборочно указать, какие именно изменения должны попасть в коммит (git add file.py, git add . — все изменения).

git commit — фиксирует подготовленные изменения в локальной истории репозитория, создавая новый коммит с уникальным хешем, автором, датой и сообщением (git commit -m "Описание изменений"). После коммита изменения сохраняются в базе данных Git и могут быть восстановлены или отменены.

Последовательность применения:

git status — проверить, какие файлы изменены (необязательно, но рекомендуется).

git add <файлы> — подготовить нужные изменения к коммиту.

git commit -m "Сообщение" — зафиксировать подготовленные изменения в локальной истории.

То есть git add предшествует git commit: сначала изменения «отбираются» в индекс, затем фиксируются. Без git add команда git commit не увидит новых изменений (кроме уже отслеживаемых файлов при использовании флага -a).

3. Что делает команда git push
git push отправляет (выгружает) коммиты из локального репозитория в удалённый (например, на GitHub). Она синхронизирует локальную ветку с удалённой: после выполнения команды изменения, зафиксированные через commit, становятся доступны другим участникам проекта на сервере.

Типичный синтаксис:

text
git push origin main
где origin — имя удалённого репозитория (по умолчанию), main — имя ветки. При первом push новой ветки используется флаг -u (git push -u origin main) для установки связи «отслеживания» между локальной и удалённой ветками, после чего достаточно писать просто git push.

Команда не добавляет и не коммитит изменения — она лишь передаёт уже зафиксированные коммиты на сервер. Если в удалённом репозитории есть новые коммиты, которых нет локально, push будет отклонён до выполнения git pull (синхронизации).

4. Зачем нужна команда git status
git status — информационная команда, которая показывает текущее состояние рабочего каталога и области подготовленных изменений относительно последнего коммита. Она не изменяет репозиторий, а только выводит отчёт.

Команда позволяет узнать:

какие файлы изменены, но ещё не добавлены в индекс (Changes not staged for commit);

какие файлы подготовлены к коммиту (Changes to be committed);

какие файлы являются неотслеживаемыми (Untracked files) — новыми, которые Git ещё не знает;

в какой ветке находится пользователь и синхронизирована ли она с удалённой (Your branch is up to date with 'origin/main');

есть ли конфликты при слиянии или незавершённые операции (merge, rebase).

Зачем нужна: git status — основной инструмент контроля перед выполнением add и commit. Она помогает не забыть добавить нужные файлы, не закоммитить лишнее, понять, на каком этапе работы находится проект, и вовремя заметить конфликты. Это «навигатор» по состояниям Git, который рекомендуется запускать перед каждой операцией фиксации изменений.
